Each phase flows into the next: clean the data (Phase 2) before creating new signal from it (Phase 3), create before selecting what's worth keeping (Phase 4), and reduce dimensionality (Phase 5) only once you know what survived selection. Phase 3 now covers feature creation across every raw data type — time, text, images, and domain-driven business behavior — and Phase 4 pairs classic selection methods with the importance/interpretability tools that answer the same "what actually matters?" question. Phase 6 is where all of this meets the real world: keeping features honest (no leakage), reproducible (pipelines), documented (metadata), and reliably served (feature stores).
Where Feature Engineering Hands Off to MLOps
The exact same pipeline, followed end to end — dataset in, live URL out
Raw dataset (.csv) → Feature Engineering (Phases 1–6) → sklearn Pipeline trained → MLflow tracking → model.joblib + Model Registry → FastAPI (/predict) → Streamlit UI → Docker image → Docker Hub → AWS EC2 (live) → Monitoring & drift → ↺ Retrain — back to Feature Engineering

This is not a one-way line — it's a loop. Drift detection on live traffic feeds straight back into re-running Phases 1–6 on fresh data, retraining, and re-deploying. Everything to the left of the arrow into "MLflow tracking" is the Feature Engineering half of this course; everything from there onward is the MLOps half, below.

The MLOps half picks up exactly where Feature Engineering leaves off: a trained sklearn.Pipeline is tracked (Phase 9) before it's ever trusted, packaged as model.joblib and served by exactly one process — FastAPI (Phase 10) — so a Streamlit UI, a Docker container, and an AWS server can all reach the same predictions through the same door. Docker (Phase 11) freezes that whole environment so it behaves identically on a laptop, in CI, and on AWS EC2. None of this is separate from Feature Engineering — Phase 12's drift detection exists specifically to notice when the world has drifted away from the features Phase 1–6 were built on, which is exactly when the retrain loop sends you back to the start.
